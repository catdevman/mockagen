# Introspection queries

The catalog SQL behind `mockagen schema`, one section per dialect, for task
T1.3 in [import-tooling-tasks.md](import-tooling-tasks.md). The facts each query
has to produce are listed in
[import-tooling.md](import-tooling.md#kind-schema).

**Every query here was run against a real server** - `postgres:17-alpine`,
`mysql:8.4`, `mcr.microsoft.com/mssql/server:2022-latest` and the local
`sqlite3`, the same four the integration tests use - against the fixture tables
below, and the output shown is what came back. They are written with
placeholders; the literals were substituted when verifying. Placeholder style
differs per dialect and is in the [divergences](#where-the-four-disagree) table.

The fixture covers one of everything the schema file records: a primary key, an
identity column, `NOT NULL`, single- and multi-column `UNIQUE`, a literal
default, an expression default, `varchar(n)`, `numeric(p,s)`, an enum or its
CHECK equivalent, a foreign key, and a column comment.

## PostgreSQL

### Fixture

```sql
CREATE TYPE user_status AS ENUM ('active', 'suspended', 'closed');
CREATE TABLE public.orgs (
  id        bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name      varchar(100) NOT NULL
);
CREATE TABLE public.users (
  id          uuid NOT NULL DEFAULT gen_random_uuid() PRIMARY KEY,
  seq         bigint GENERATED BY DEFAULT AS IDENTITY,
  email       varchar(255) NOT NULL UNIQUE,
  full_name   text,
  status      user_status NOT NULL DEFAULT 'active',
  tier        char(2) CHECK (tier IN ('aa', 'bb', 'cc')),
  balance     numeric(12,2) NOT NULL DEFAULT 0.00,
  login_count integer,
  signed_up   timestamptz NOT NULL DEFAULT now(),
  org_id      bigint NOT NULL REFERENCES public.orgs(id),
  CONSTRAINT users_org_email_uniq UNIQUE (org_id, email)
);
COMMENT ON COLUMN public.users.email IS 'login address';
```

### Columns

Use `pg_catalog`, not `information_schema`. The latter reports `sql_type` as
`character varying` with the length stripped, and `format_type` is the only
thing that gives the spelling back the way the server writes it.

```sql
SELECT a.attnum                             AS ordinal,
       a.attname                            AS name,
       format_type(a.atttypid, a.atttypmod) AS sql_type,
       t.typname                            AS base_type,
       t.typtype = 'e'                      AS is_enum,
       NOT a.attnotnull                     AS nullable,
       pg_get_expr(ad.adbin, ad.adrelid)    AS default_expr,
       a.attidentity                        AS identity,
       information_schema._pg_char_max_length(a.atttypid, a.atttypmod)
                                            AS max_length,
       information_schema._pg_numeric_precision(a.atttypid, a.atttypmod)
                                            AS numeric_precision,
       information_schema._pg_numeric_scale(a.atttypid, a.atttypmod)
                                            AS numeric_scale,
       col_description(a.attrelid, a.attnum) AS comment
FROM pg_attribute a
JOIN pg_class cl     ON cl.oid = a.attrelid
JOIN pg_namespace ns ON ns.oid = cl.relnamespace
JOIN pg_type t       ON t.oid = a.atttypid
LEFT JOIN pg_attrdef ad ON ad.adrelid = a.attrelid AND ad.adnum = a.attnum
WHERE ns.nspname = $1 AND cl.relname = $2
  AND a.attnum > 0 AND NOT a.attisdropped
ORDER BY a.attnum;
```

```
 ordinal |    name     |         sql_type         |  base_type  | is_enum | nullable |     default_expr      | identity | max_length | numeric_precision | numeric_scale |    comment
---------+-------------+--------------------------+-------------+---------+----------+-----------------------+----------+------------+-------------------+---------------+---------------
       1 | id          | uuid                     | uuid        | f       | f        | gen_random_uuid()     |          |            |                   |               |
       2 | seq         | bigint                   | int8        | f       | f        |                       | d        |            |                64 |             0 |
       3 | email       | character varying(255)   | varchar     | f       | f        |                       |          |        255 |                   |               | login address
       4 | full_name   | text                     | text        | f       | t        |                       |          |            |                   |               |
       5 | status      | user_status              | user_status | t       | f        | 'active'::user_status |          |            |                   |               |
       6 | tier        | character(2)             | bpchar      | f       | t        |                       |          |          2 |                   |               |
       7 | balance     | numeric(12,2)            | numeric     | f       | f        | 0.00                  |          |            |                12 |             2 |
       8 | login_count | integer                  | int4        | f       | t        |                       |          |            |                32 |             0 |
       9 | signed_up   | timestamp with time zone | timestamptz | f       | f        | now()                 |          |            |                   |               |
      10 | org_id      | bigint                   | int8        | f       | f        |                       |          |            |                64 |             0 |
```

`a.attidentity` is `''` for none, `'a'` for `GENERATED ALWAYS` and `'d'` for
`GENERATED BY DEFAULT`. The distinction matters to the importer, not just the
generator: `ALWAYS` rejects an explicit value outright, while `BY DEFAULT`
accepts one. Only `ALWAYS` must be dropped from an `INSERT`.

`NOT a.attnotnull` is not a typo - the catalog stores the negative.
`is_enum` is what tells you which types to fetch labels for.

The two `information_schema._pg_*` functions are undocumented but stable, and
are how `information_schema.columns` itself derives those three values. The
alternative is decoding `atttypmod` by hand (`((atttypmod - 4) >> 16) & 65535`
for numeric precision), which is the same arithmetic with more places to get it
wrong.

### Constraints

One query covers primary key, unique, foreign key and check. A composite
constraint comes back as one row per column, ordered - which is what the double
`unnest ... WITH ORDINALITY` is for, including the join that lines each foreign
key column up with the referenced column at the same position.

```sql
SELECT con.conname                   AS name,
       con.contype                   AS kind,   -- p | u | f | c
       k.ord                         AS position,
       a.attname                     AS column_name,
       fns.nspname                   AS ref_schema,
       fcl.relname                   AS ref_table,
       fa.attname                    AS ref_column,
       pg_get_constraintdef(con.oid) AS definition
FROM pg_constraint con
JOIN pg_class cl     ON cl.oid = con.conrelid
JOIN pg_namespace ns ON ns.oid = cl.relnamespace
LEFT JOIN unnest(con.conkey)  WITH ORDINALITY AS k(attnum, ord)  ON true
LEFT JOIN pg_attribute a   ON a.attrelid = con.conrelid AND a.attnum = k.attnum
LEFT JOIN unnest(con.confkey) WITH ORDINALITY AS fk(attnum, ord) ON fk.ord = k.ord
LEFT JOIN pg_class fcl     ON fcl.oid = con.confrelid
LEFT JOIN pg_namespace fns ON fns.oid = fcl.relnamespace
LEFT JOIN pg_attribute fa  ON fa.attrelid = con.confrelid AND fa.attnum = fk.attnum
WHERE ns.nspname = $1 AND cl.relname = $2
ORDER BY con.contype, con.conname, k.ord;
```

```
         name         | kind | position | column_name | ref_schema | ref_table | ref_column |                               definition
----------------------+------+----------+-------------+------------+-----------+------------+------------------------------------------------------------------------
 users_tier_check     | c    |        1 | tier        |            |           |            | CHECK ((tier = ANY (ARRAY['aa'::bpchar, 'bb'::bpchar, 'cc'::bpchar])))
 users_org_id_fkey    | f    |        1 | org_id      | public     | orgs      | id         | FOREIGN KEY (org_id) REFERENCES orgs(id)
 users_pkey           | p    |        1 | id          |            |           |            | PRIMARY KEY (id)
 users_email_key      | u    |        1 | email       |            |           |            | UNIQUE (email)
 users_org_email_uniq | u    |        1 | org_id      |            |           |            | UNIQUE (org_id, email)
 users_org_email_uniq | u    |        2 | email       |            |           |            | UNIQUE (org_id, email)
```

Set a column's `unique` fact only from a **single-column** unique constraint.
`users_org_email_uniq` constrains the pair, and marking `email` unique because
of it would be wrong.

### Enum labels

```sql
SELECT t.typname AS type_name, e.enumlabel AS value
FROM pg_type t
JOIN pg_enum e      ON e.enumtypid = t.oid
JOIN pg_namespace n ON n.oid = t.typnamespace
WHERE n.nspname = $1 AND t.typname = ANY ($2)
ORDER BY t.typname, e.enumsortorder;
```

Labels come back one per row, in declaration order, unescaped - so a label
containing a comma, a quote or a colon needs no parsing at all. Postgres is the
only one of the four where that is true. `ORDER BY e.enumsortorder` rather than
by oid: reordering an enum with `ALTER TYPE ... BEFORE` leaves the oids out of
sequence.

### Tables

```sql
SELECT ns.nspname           AS schema,
       cl.relname           AS name,
       cl.reltuples::bigint AS approx_rows
FROM pg_class cl
JOIN pg_namespace ns ON ns.oid = cl.relnamespace
WHERE cl.relkind IN ('r', 'p')
  AND ns.nspname NOT IN ('pg_catalog', 'information_schema')
ORDER BY ns.nspname, cl.relname;
```

`reltuples` is **-1**, not 0, for a table that has never been analysed (since
PG 14). Render that as unknown; showing "0 rows" for a full table is worse than
showing nothing.

## MySQL

### Fixture

```sql
CREATE TABLE users (
  id          CHAR(36) NOT NULL,
  seq         BIGINT NOT NULL AUTO_INCREMENT,
  email       VARCHAR(255) NOT NULL COMMENT 'login address',
  full_name   TEXT,
  status      ENUM('active','suspended','closed') NOT NULL DEFAULT 'active',
  tier        CHAR(2),
  balance     DECIMAL(12,2) NOT NULL DEFAULT 0.00,
  login_count INT,
  signed_up   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  org_id      BIGINT NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY users_seq_uniq (seq),
  UNIQUE KEY users_email_key (email),
  UNIQUE KEY users_org_email_uniq (org_id, email),
  CONSTRAINT users_tier_check CHECK (tier IN ('aa','bb','cc')),
  CONSTRAINT users_org_id_fkey FOREIGN KEY (org_id) REFERENCES orgs(id)
) ENGINE=InnoDB;
```

### Columns

```sql
SELECT ORDINAL_POSITION         AS ordinal,
       COLUMN_NAME              AS name,
       COLUMN_TYPE              AS sql_type,
       DATA_TYPE                AS base_type,
       IS_NULLABLE = 'YES'      AS nullable,
       COLUMN_DEFAULT           AS default_expr,
       EXTRA                    AS extra,
       CHARACTER_MAXIMUM_LENGTH AS max_length,
       NUMERIC_PRECISION        AS numeric_precision,
       NUMERIC_SCALE            AS numeric_scale,
       COLUMN_COMMENT           AS comment
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = ? AND TABLE_NAME = ?
ORDER BY ORDINAL_POSITION;
```

```
| ordinal | name        | sql_type                            | base_type | nullable | default_expr      | extra             | max_length | numeric_precision | numeric_scale | comment       |
|       1 | id          | char(36)                            | char      |        0 | NULL              |                   |         36 |              NULL |          NULL |               |
|       2 | seq         | bigint                              | bigint    |        0 | NULL              | auto_increment    |       NULL |                19 |             0 |               |
|       3 | email       | varchar(255)                        | varchar   |        0 | NULL              |                   |        255 |              NULL |          NULL | login address |
|       4 | full_name   | text                                | text      |        1 | NULL              |                   |      65535 |              NULL |          NULL |               |
|       5 | status      | enum('active','suspended','closed') | enum      |        0 | active            |                   |          9 |              NULL |          NULL |               |
|       6 | tier        | char(2)                             | char      |        1 | NULL              |                   |          2 |              NULL |          NULL |               |
|       7 | balance     | decimal(12,2)                       | decimal   |        0 | 0.00              |                   |       NULL |                12 |             2 |               |
|       8 | login_count | int                                 | int       |        1 | NULL              |                   |       NULL |                10 |             0 |               |
|       9 | signed_up   | datetime                            | datetime  |        0 | CURRENT_TIMESTAMP | DEFAULT_GENERATED |       NULL |              NULL |          NULL |               |
|      10 | org_id      | bigint                              | bigint    |        0 | NULL              |                   |       NULL |                19 |             0 |               |
```

Three things to take from this:

- **MySQL has no enum catalog.** The values are inside `COLUMN_TYPE` as
  `enum('active','suspended','closed')` and must be parsed out. They are
  single-quoted, comma-separated, and **a quote inside a label is doubled**: the
  labels `plain`, `has, comma`, `has'quote`, `has:colon` come back as
  `enum('plain','has, comma','has''quote','has:colon')`. A `split(",")` corrupts
  that. Parse respecting quotes.
- **`EXTRA` is what distinguishes a literal default from an expression one.**
  `balance` has `COLUMN_DEFAULT` `0.00` and no `EXTRA`; `signed_up` has
  `CURRENT_TIMESTAMP` and `EXTRA = DEFAULT_GENERATED`. Without reading `EXTRA`
  you cannot tell the string `CURRENT_TIMESTAMP` from a call to it. `EXTRA` also
  carries `auto_increment`, which is MySQL's identity.
- **`max_length` is meaningless for an enum** - it reports 9, the longest label.
  Do not carry it as a length.

### Constraints

```sql
SELECT tc.CONSTRAINT_NAME          AS name,
       tc.CONSTRAINT_TYPE          AS kind,
       kcu.ORDINAL_POSITION        AS position,
       kcu.COLUMN_NAME             AS column_name,
       kcu.REFERENCED_TABLE_SCHEMA AS ref_schema,
       kcu.REFERENCED_TABLE_NAME   AS ref_table,
       kcu.REFERENCED_COLUMN_NAME  AS ref_column,
       cc.CHECK_CLAUSE             AS definition
FROM information_schema.TABLE_CONSTRAINTS tc
LEFT JOIN information_schema.KEY_COLUMN_USAGE kcu
       ON kcu.CONSTRAINT_SCHEMA = tc.CONSTRAINT_SCHEMA
      AND kcu.CONSTRAINT_NAME   = tc.CONSTRAINT_NAME
      AND kcu.TABLE_NAME        = tc.TABLE_NAME
LEFT JOIN information_schema.CHECK_CONSTRAINTS cc
       ON cc.CONSTRAINT_SCHEMA = tc.CONSTRAINT_SCHEMA
      AND cc.CONSTRAINT_NAME   = tc.CONSTRAINT_NAME
WHERE tc.TABLE_SCHEMA = ? AND tc.TABLE_NAME = ?
ORDER BY tc.CONSTRAINT_TYPE, tc.CONSTRAINT_NAME, kcu.ORDINAL_POSITION;
```

```
| name                 | kind        | position | column_name | ref_schema | ref_table | ref_column | definition                                                 |
| users_tier_check     | CHECK       |     NULL | NULL        | NULL       | NULL      | NULL       | (`tier` in (_utf8mb4\'aa\',_utf8mb4\'bb\',_utf8mb4\'cc\')) |
| users_org_id_fkey    | FOREIGN KEY |        1 | org_id      | mockagen   | orgs      | id         | NULL                                                       |
| PRIMARY              | PRIMARY KEY |        1 | id          | NULL       | NULL      | NULL       | NULL                                                       |
| users_email_key      | UNIQUE      |        1 | email       | NULL       | NULL      | NULL       | NULL                                                       |
| users_org_email_uniq | UNIQUE      |        1 | org_id      | NULL       | NULL      | NULL       | NULL                                                       |
| users_org_email_uniq | UNIQUE      |        2 | email       | NULL       | NULL      | NULL       | NULL                                                       |
| users_seq_uniq       | UNIQUE      |        1 | seq         | NULL       | NULL      | NULL       | NULL                                                       |
```

- **A CHECK constraint has no `KEY_COLUMN_USAGE` rows**, so `column_name` is
  NULL and the owning column has to come out of `CHECK_CLAUSE`. MySQL is the
  only dialect of the four that will not tell you which column a check belongs
  to.
- The clause text is stored with **charset introducers and backslash-escaped
  quotes**. That is not the client's formatting: with escaping disabled, the
  bytes are `(`tier` in (_utf8mb4\'aa\',_utf8mb4\'bb\',_utf8mb4\'cc\'))`. Strip
  the `_utf8mb4` introducers and unescape `\'` before parsing.
- The primary key constraint is always named `PRIMARY`.

### Tables

```sql
SELECT TABLE_SCHEMA AS `schema`, TABLE_NAME AS name, TABLE_ROWS AS approx_rows
FROM information_schema.TABLES
WHERE TABLE_TYPE = 'BASE TABLE'
  AND TABLE_SCHEMA NOT IN ('mysql', 'information_schema',
                           'performance_schema', 'sys')
ORDER BY TABLE_SCHEMA, TABLE_NAME;
```

`TABLE_ROWS` is an InnoDB estimate and can be off by an order of magnitude; it
is 0 for an empty table, so unlike postgres there is no unknown sentinel.

### Columns

SQL Server is the one dialect with **no column holding the type spelling**, so
it has to be assembled. `max_length` is in **bytes** - `nvarchar(255)` reports
510 - and `-1` means `MAX`.

```sql
SELECT c.column_id AS ordinal,
       c.name      AS name,
       ty.name + CASE
         WHEN ty.name IN ('varchar', 'char', 'varbinary', 'binary')
           THEN '(' + IIF(c.max_length = -1, 'max',
                          CAST(c.max_length AS varchar(11))) + ')'
         WHEN ty.name IN ('nvarchar', 'nchar')
           THEN '(' + IIF(c.max_length = -1, 'max',
                          CAST(c.max_length / 2 AS varchar(11))) + ')'
         WHEN ty.name IN ('decimal', 'numeric')
           THEN '(' + CAST(c.precision AS varchar(11)) + ',' +
                      CAST(c.scale AS varchar(11)) + ')'
         WHEN ty.name IN ('datetime2', 'time', 'datetimeoffset')
           THEN '(' + CAST(c.scale AS varchar(11)) + ')'
         ELSE '' END AS sql_type,
       ty.name       AS base_type,
       CASE WHEN ty.name IN ('varchar', 'char', 'varbinary', 'binary')
                 AND c.max_length <> -1 THEN c.max_length
            WHEN ty.name IN ('nvarchar', 'nchar')
                 AND c.max_length <> -1 THEN c.max_length / 2
            ELSE NULL END AS max_length,
       CASE WHEN ty.name IN ('decimal', 'numeric') THEN c.precision
            ELSE NULL END AS numeric_precision,
       CASE WHEN ty.name IN ('decimal', 'numeric') THEN c.scale
            ELSE NULL END AS numeric_scale,
       c.is_nullable,
       c.is_identity,
       dc.definition                   AS default_expr,
       CAST(ep.value AS nvarchar(200)) AS comment
FROM sys.columns c
JOIN sys.objects o ON o.object_id = c.object_id
JOIN sys.schemas s ON s.schema_id = o.schema_id
JOIN sys.types ty  ON ty.user_type_id = c.user_type_id
LEFT JOIN sys.default_constraints dc
       ON dc.parent_object_id = c.object_id AND dc.parent_column_id = c.column_id
LEFT JOIN sys.extended_properties ep
       ON ep.major_id = c.object_id AND ep.minor_id = c.column_id
      AND ep.name = 'MS_Description'
WHERE s.name = @p1 AND o.name = @p2
ORDER BY c.column_id;
```

```
ordinal name        sql_type         max_length numeric_precision numeric_scale is_nullable is_identity default_expr
1       id          uniqueidentifier NULL       NULL              NULL          0           0           (newid())
2       seq         bigint           NULL       NULL              NULL          0           1           NULL
3       email       nvarchar(255)    255        NULL              NULL          0           0           NULL
4       full_name   nvarchar(max)    NULL       NULL              NULL          1           0           NULL
5       status      nvarchar(20)     20         NULL              NULL          0           0           ('active')
6       tier        char(2)          2          NULL              NULL          1           0           NULL
7       balance     decimal(12,2)    NULL       12                2             0           0           ((0.00))
8       login_count int              NULL       NULL              NULL          1           0           NULL
9       signed_up   datetime2(7)     NULL       NULL              NULL          0           0           (sysutcdatetime())
10      org_id      bigint           NULL       NULL              NULL          0           0           NULL
```

- **Identity is `sys.columns.is_identity`.** `information_schema.COLUMNS` has no
  equivalent on this server, which is the reason to use `sys.*` here at all;
  `sys.identity_columns` is for the seed and increment, not for the flag.
- **Defaults come back parenthesised**, and numerics doubly so: `('active')`,
  `((0.00))`, `(newid())`. Strip the outer layers before storing.
- `c.precision` is populated for every numeric-ish type, including
  `datetime2` (27), so scope it to `decimal`/`numeric` or it means nothing.
- **`identity` is a reserved word in T-SQL**, so `AS identity` is a syntax
  error. Alias it `is_identity`, or bracket it.

### Constraints

Three catalogs, unioned into the same shape postgres produces. Note that the
`CAST(NULL AS ...)` in the first branch is what fixes the column types for the
union.

```sql
SELECT kc.name                     AS name,
       IIF(kc.type = 'PK', 'p', 'u') AS kind,
       CAST(ic.key_ordinal AS int) AS position,
       col.name                    AS column_name,
       CAST(NULL AS sysname)       AS ref_schema,
       CAST(NULL AS sysname)       AS ref_table,
       CAST(NULL AS sysname)       AS ref_column,
       CAST(NULL AS nvarchar(max)) AS definition
FROM sys.key_constraints kc
JOIN sys.objects o        ON o.object_id = kc.parent_object_id
JOIN sys.schemas s        ON s.schema_id = o.schema_id
JOIN sys.index_columns ic ON ic.object_id = kc.parent_object_id
                         AND ic.index_id = kc.unique_index_id
JOIN sys.columns col      ON col.object_id = ic.object_id
                         AND col.column_id = ic.column_id
WHERE s.name = @p1 AND o.name = @p2
UNION ALL
SELECT fk.name, 'f', CAST(fkc.constraint_column_id AS int), pcol.name,
       rs.name, rt.name, rcol.name, CAST(NULL AS nvarchar(max))
FROM sys.foreign_keys fk
JOIN sys.objects o    ON o.object_id = fk.parent_object_id
JOIN sys.schemas s    ON s.schema_id = o.schema_id
JOIN sys.foreign_key_columns fkc ON fkc.constraint_object_id = fk.object_id
JOIN sys.columns pcol ON pcol.object_id = fkc.parent_object_id
                     AND pcol.column_id = fkc.parent_column_id
JOIN sys.objects rt   ON rt.object_id = fk.referenced_object_id
JOIN sys.schemas rs   ON rs.schema_id = rt.schema_id
JOIN sys.columns rcol ON rcol.object_id = fkc.referenced_object_id
                     AND rcol.column_id = fkc.referenced_column_id
WHERE s.name = @p1 AND o.name = @p2
UNION ALL
SELECT cc.name, 'c', 1, col.name,
       NULL, NULL, NULL, CAST(cc.definition AS nvarchar(max))
FROM sys.check_constraints cc
JOIN sys.objects o ON o.object_id = cc.parent_object_id
JOIN sys.schemas s ON s.schema_id = o.schema_id
LEFT JOIN sys.columns col ON col.object_id = cc.parent_object_id
                         AND col.column_id = cc.parent_column_id
WHERE s.name = @p1 AND o.name = @p2
ORDER BY kind, name, position;
```

```
name               kind position column_name ref_schema ref_table ref_column definition
users_status_check c    1        status      NULL       NULL      NULL       ([status]='closed' OR [status]='suspended' OR [status]='active')
users_org_id_fkey  f    1        org_id      dbo        orgs      id         NULL
users_pk           p    1        id          NULL       NULL      NULL       NULL
users_email_key    u    1        email       NULL       NULL      NULL       NULL
users_org_email_uniq u  1        org_id      NULL       NULL      NULL       NULL
users_org_email_uniq u  2        email       NULL       NULL      NULL       NULL
users_seq_uniq     u    1        seq         NULL       NULL      NULL       NULL
```

`sys.check_constraints.parent_column_id` is 0 for a table-level check, which the
`LEFT JOIN` turns into a NULL `column_name`. Unique indexes created with
`CREATE UNIQUE INDEX` rather than a constraint do not appear in
`sys.key_constraints`; add `sys.indexes WHERE is_unique = 1 AND
is_unique_constraint = 0` if those should count.

### Tables

```sql
SELECT s.name AS [schema], t.name AS name, SUM(p.rows) AS approx_rows
FROM sys.tables t
JOIN sys.schemas s    ON s.schema_id = t.schema_id
JOIN sys.partitions p ON p.object_id = t.object_id AND p.index_id IN (0, 1)
GROUP BY s.name, t.name
ORDER BY s.name, t.name;
```

## SQLite

Driven through the `sqlite3` CLI with `-json`, not a Go driver - see
[the dependency section](import-tooling.md#dependencies) for why.

### Fixture

```sql
CREATE TABLE users (
  id          TEXT NOT NULL PRIMARY KEY,
  seq         INTEGER,
  email       TEXT NOT NULL UNIQUE,
  full_name   TEXT,
  status      TEXT NOT NULL DEFAULT 'active'
              CHECK (status IN ('active', 'suspended', 'closed')),
  tier        CHAR(2) CHECK (tier IN ('aa', 'bb', 'cc')),
  balance     NUMERIC(12,2) NOT NULL DEFAULT 0.00,
  login_count INTEGER,
  signed_up   TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  org_id      INTEGER NOT NULL REFERENCES orgs(id),
  UNIQUE (org_id, email)
);
```

### Columns

```sql
SELECT cid AS ordinal, name, type AS sql_type,
       "notnull", dflt_value AS default_expr, pk
FROM pragma_table_info('users')
ORDER BY cid;
```

```json
[{"ordinal":0,"name":"id","sql_type":"TEXT","notnull":1,"default_expr":null,"pk":1},
 {"ordinal":4,"name":"status","sql_type":"TEXT","notnull":1,"default_expr":"'active'","pk":0},
 {"ordinal":5,"name":"tier","sql_type":"CHAR(2)","notnull":0,"default_expr":null,"pk":0},
 {"ordinal":6,"name":"balance","sql_type":"NUMERIC(12,2)","notnull":1,"default_expr":"0.00","pk":0},
 {"ordinal":8,"name":"signed_up","sql_type":"TEXT","notnull":1,"default_expr":"CURRENT_TIMESTAMP","pk":0}]
```

`cid` is **0-based**; the other three dialects are 1-based. `pk` is the column's
1-based position within the primary key, or 0 - so a composite primary key needs
no separate query. The declared type is stored verbatim, including
`NUMERIC(12,2)`, which is a declaration rather than a constraint: sqlite applies
type affinity and will store anything.

Use `pragma_table_xinfo` instead if generated and hidden columns matter.

### Checks and autoincrement

There is no pragma for either. `sqlite_master.sql` holds the original `CREATE
TABLE` text, so it is the only source:

```sql
SELECT sql FROM sqlite_master WHERE type = 'table' AND name = ?;
```

The upside is that sqlite is the **only** one of the four that gives the check
back exactly as it was written - `CHECK (status IN ('active', 'suspended',
'closed'))` - because it stores the DDL rather than a parsed form. The downside
is that there is nothing else: `AUTOINCREMENT` can only be found by looking for
the keyword in that text, which will also match a column named `autoincrement`
or a comment mentioning it. Treat it as a hint, and note that `INTEGER PRIMARY
KEY` is an alias for the rowid and autoincrements whether or not the keyword is
present.

### Tables

```sql
SELECT name FROM sqlite_master
WHERE type = 'table' AND name NOT LIKE 'sqlite_%'
ORDER BY name;
```

No row estimate exists; `COUNT(*)` is the only answer and it is a full scan.
Show nothing rather than paying for it on the table-picker screen.

## Where the four disagree

| | postgres | mysql | mssql | sqlite |
|---|---|---|---|---|
| Placeholder | `$1` | `?` | `@p1` | `?` |
| Catalog | `pg_catalog` | `information_schema` | `sys.*` | pragmas + `sqlite_master` |
| Ordinal base | 1 | 1 | 1 | **0** |
| Type spelling | `format_type()` | `COLUMN_TYPE` | **assemble it** | verbatim DDL |
| `max_length` unit | characters | characters | **bytes**, `-1` = MAX | n/a |
| Identity | `attidentity` `a`/`d` | `EXTRA` = `auto_increment` | `is_identity` | `AUTOINCREMENT` in DDL text |
| Default: literal vs expression | `pg_get_expr` text | needs `EXTRA` | parenthesised | DDL text |
| Enum values | `pg_enum`, one row each | parse `COLUMN_TYPE` | no enum type at all | parse DDL |
| Check's owning column | yes | **no** | yes (0 = table-level) | parse DDL |
| Row estimate | `reltuples`, **-1 = unknown** | `TABLE_ROWS` | `sys.partitions` | none |
| Column comments | `col_description` | `COLUMN_COMMENT` | extended properties | none |

The row that costs the most work is **enum values**, because the thing
`rule:enum` wants - an ordered list of allowed values - survives in only one of
the four. Given `CHECK (x IN ('aa','bb','cc'))`, the catalogs return:

| dialect | what comes back |
|---|---|
| postgres | `CHECK ((tier = ANY (ARRAY['aa'::bpchar, 'bb'::bpchar, 'cc'::bpchar])))` |
| mysql | ``(`tier` in (_utf8mb4\'aa\',_utf8mb4\'bb\',_utf8mb4\'cc\'))`` |
| mssql | `([status]='closed' OR [status]='suspended' OR [status]='active')` |
| sqlite | `CHECK (status IN ('active', 'suspended', 'closed'))` |

So: postgres rewrites `IN` to `= ANY (ARRAY[...])` and appends a cast to every
element; mysql keeps `in` but adds charset introducers and escapes the quotes;
**mssql rewrites it to an OR-chain of equalities and reverses the order**; only
sqlite is verbatim. A single "parse the IN list" routine will not work. Write
one small parser per dialect, have each return `(column, values, ok)` and bail
to `ok = false` on anything it does not recognise, and accept that **mssql
cannot recover the declared order** - sort those values or present them as a set.

A true enum type exists only in postgres and mysql, and there the values are
exact: postgres hands them back unescaped, one per row, and mysql needs only the
quote-aware split. Prefer the enum path and treat CHECK parsing as the
best-effort fallback it is.

Two closing notes. Everything above reads one table; the TUI's table picker uses
the per-dialect table query, and nothing here needs a cross-table query because
[a schema file is one table](import-tooling.md#the-pipeline). And none of these
queries cover computed or generated columns, partitioned-table parents, or
domain types - if a fixture grows one, the per-dialect test will say so.
